# اولین اجرا و بهره‌برداری روزانه — Ninja Image Hub v0.6

این سند مکمل [START_HERE_V6_FA.md](../START_HERE_V6_FA.md) است و فرض می‌کند نصب پایه انجام شده است. هدف، رساندن شما از clone تازه به اولین تصویر تأییدشده و سپس ادارهٔ روزانهٔ امن است.

> این پروژه ابزار محلی و آزمایشی است. اتوماسیون رابط ChatGPT ممکن است خلاف شرایط استفادهٔ OpenAI باشد و به تعلیق حساب منجر شود. هیچ بخشی از این سند تضمین ظرفیت یا SLA نیست.

## ۱. پیش‌نیازهای دقیق

| مورد | چرا لازم است | بررسی سریع |
|---|---|---|
| Python 3.11+ | اجرای FastAPI و تست‌ها | `python --version` |
| Node.js 22+ و npm | اجرای دروازهٔ مرورگر و نصب وابستگی‌های آن | `node --version`، `npm --version` |
| Git | clone کردن دروازه در `prepare_gateway.py` | `git --version` |
| Google Chrome | patchright مرورگر واقعی Chrome را کنترل می‌کند | نصب معمول ویندوز |
| فضای دیسک | تصاویر اصلی ۲ تا ۵ MiB برای هر PNG؛ پیش‌نمایش/ZIP هم فضا می‌خواهند | doctor مقدار آزاد را نشان می‌دهد |
| دسترسی به اینترنت | فقط در زمان نصب وابستگی‌ها و کار واقعی با ChatGPT | — |

اگر روی لینوکس اجرا می‌کنید، worker برای باز کردن مرورگر به نمایشگر واقعی یا `xvfb-run` نیاز دارد؛ Hub خودش این را بررسی می‌کند و در نبود آن شروع worker را رد می‌کند.

## ۲. doctor چه چیزهایی را بررسی می‌کند

```powershell
python scripts/doctor.py
```

خروج ۰ یعنی «آمادهٔ شروع»؛ خروج ۱ یعنی حداقل یک FAIL. با `--json` همان نتیجه به‌صورت ماشین‌خوان برمی‌گردد. دسته‌های بررسی:

| دسته | بررسی | FAIL/WARN معمول و رفع |
|---|---|---|
| Python | نسخهٔ 3.11+ و importهای runtime (fastapi، sqlalchemy، httpx، PIL، dotenv، psutil، itsdangerous) | `pip install -r requirements.txt` |
| Node | Node 22+، وجود npm و git | نصب Node/Git و بازکردن ترمینال جدید |
| Secrets | وجود `.env` و قدرت `APP_SECRET` (۳۲+) و `ADMIN_PASSWORD` (۱۲+) | `python scripts/bootstrap.py` برای نصب تازه؛ در نصب موجود از بک‌آپ برگردانید |
| MIME | `.js` و `.css` درست resolve شوند | پنل MIME را pin می‌کند؛ برای سرو دستی از `scripts/serve_preview.py` استفاده کنید |
| داده | `DATA_DIR` قابل نوشتن و فضای آزاد | `DATA_DIR` قابل‌نوشتن انتخاب کنید؛ فضای دیسک آزاد کنید |
| دیتابیس | SQLite در حالت WAL | اگر WAL نیست، یک بار پنل را اجرا کنید تا اعمال شود. PostgreSQL توسط doctor بررسی نمی‌شود |
| دروازه | وجود `vendor/gpt-web-gateway/src/server.js`، `node_modules`، `PINNED_COMMIT.txt`، کش Playwright و Chrome واقعی | `python scripts/prepare_gateway.py`؛ Chrome را نصب کنید |
| پورت‌ها | پورت پنل و بازهٔ workerها | `--port` آزاد؛ فقط یک Uvicorn |

**PASS** یعنی بررسی موفق بود. **WARN** یعنی مانع شروع نیست ولی باید تصمیم بگیرید (مثلاً `AGENT_API_KEY` خالی است و API ایجنت غیرفعال می‌ماند، یا پورت ۸۰۸۰ اشغال است). **FAIL** یعنی شروع یا کارکرد درست ممکن نیست؛ خط `->` فرمان رفع را می‌دهد.

روی یک clone تازه، FAILهای `.env` و دروازه طبیعی‌اند: اول bootstrap و prepare_gateway را اجرا کنید و doctor را دوباره بزنید.

## ۳. نصب دروازهٔ مرورگر (همراه با مرورگرها)

```powershell
python scripts/prepare_gateway.py --yes
```

اسکریپت این کارها را انجام می‌دهد:

1. clone کم‌عمق از `gpt-web-gateway` در `vendor/gpt-web-gateway`.
2. ثبت commit نصب‌شده در `vendor/PINNED_COMMIT.txt`.
3. بررسی وجود `package-lock.json`؛ بدون lockfile نصب را رد می‌کند تا وابستگی‌ها بی‌قید حل نشوند.
4. `npm ci` برای نصب دقیق وابستگی‌ها.
5. `npx playwright install chromium` و `npx patchright install chrome` برای مرورگرها.

نکات:

- `--skip-browsers` را فقط وقتی بزنید که مرورگرها را دستی نصب می‌کنید؛ در غیر این‌صورت worker بالا می‌آید ولی مرورگر باز نمی‌کند.
- دروازهٔ موجود بازنویسی/به‌روزرسانی بی‌صدا نمی‌شود. اگر پوشهٔ vendor ناقص است، اسکریپت متوقف می‌شود؛ پس از بررسی دستی حذفش کنید و دوباره اجرا کنید.
- نصب دروازه به معنی تأیید امنیتی یا رسمی‌بودن آن نیست. شرایط استفاده و ریسک تعلیق حساب را بپذیرید.
- پس از نصب دوباره `python scripts/doctor.py` را بزنید؛ doctor باید Chrome و Playwright را ببیند.

## ۴. ورود دستی ChatGPT و انقضای نشست

هر حساب worker مستقل با پروفایل مرورگر جدا دارد. ورود:

1. حساب را در **Accounts** بسازید و Start کنید.
2. تا وضعیت `online` و نشست `connected` شود صبر کنید.
3. صفحهٔ `/accounts/<ACCOUNT_ID>/login` را باز کنید.
4. ورود را داخل همان صفحه، دستی و با حساب مجاز خودتان انجام دهید (شامل هر مرحلهٔ دومرحله‌ای که فعال است). Hub از MFA/CAPTCHA عبور نمی‌کند.
5. **Save** را بزنید تا نشست نگه داشته شود.

وضعیت‌های نشست:

- `connected`: probe نشست معتبر گزارش می‌دهد.
- `unverified`: worker آنلاین است اما نشست معتبر دیده نمی‌شود؛ احتمالاً ورود لازم است.
- `unknown`: probe نتوانست وضعیت را تعیین کند؛ ممکن است worker هنوز بالا نیامده باشد.

نشست ChatGPT در طول زمان منقضی می‌شود، رمز عوض شود یا challenge امنیتی ظاهر شود. در این حالت:

- Jobها ممکن است `failed` یا `unknown` شوند؛ پیش از هر اقدامی Jobs را بررسی کنید.
- دوباره از صفحهٔ login وارد شوید و Save بزنید.
- کوکی یا فایل auth را دستی بین حساب‌ها کپی نکنید؛ جداسازی حساب‌ها بخشی از قرارداد است.
- اگر پس از ورود موفق هم `unverified` می‌ماند، worker را Stop/Start کنید و لاگ `data/accounts/<id>/worker.log` را ببینید.

## ۵. اولین تصویر و تأیید بایت اصلی

1. حسابی با نشست `connected` آماده کنید.
2. در **Image Studio** پرامپت کوتاه، `n=1` و نسبت `1:1` بدهید.
3. تا وضعیت `completed` صبر کنید. تصویر باید در **Gallery** دیده شود.
4. فایل اصلی را از Gallery با `download=true` بگیرید یا مستقیماً از دیسک بردارید:

```text
<DATA_DIR>\gallery\<job_id>-1.png
```

5. برای تأیید اینکه فایل ذخیره‌شده همان بایت اصلی است، هش SHA-256 فایل را با مقدار ثبت‌شده در دیتابیس مقایسه کنید:

```powershell
Get-FileHash "data\gallery\<job_id>-1.png" -Algorithm SHA256
```

```powershell
python -c "import sqlite3; c=sqlite3.connect('data/hub.db'); print(c.execute('select image_file,image_bytes,image_sha256 from job_images order by stored_at desc limit 5').fetchall())"
```

`image_sha256` و `image_bytes` باید با فایل روی دیسک یکی باشند. اصل تصویر re-encode نمی‌شود؛ پیش‌نمایش WebP در `data/previews` فقط مشتق است و ملاک تأیید نیست.

برای Job با `n>1` چند ردیف در `job_images` با `position`های ۰ به بالا ساخته می‌شود. `partial` یعنی فقط بخشی از خروجی‌ها ذخیره شده؛ Hub خودکار بازتولید نمی‌کند.

## ۶. بک‌آپ

با WAL، کپی‌کردن تنها `hub.db` در زمان اجرا ممکن است نوشته‌های تأییدنشده را از دست بدهد. ساده‌ترین روش امن:

1. ارسال را Pause کنید و منتظر پایان Jobهای فعال بمانید.
2. فرایند Uvicorn را تمیز متوقف کنید (Ctrl+C).
3. کل `DATA_DIR` (پیش‌فرض `data/`) و `.env` را کپی کنید.

```powershell
Copy-Item -Recurse "data" "backup-data-$(Get-Date -Format yyyyMMdd)"
Copy-Item ".env" "backup-env-$(Get-Date -Format yyyyMMdd)"
```

اگر نمی‌خواهید سرویس را متوقف کنید، از backup آنلاین SQLite استفاده کنید:

```powershell
sqlite3 "data\hub.db" ".backup 'data\hub-backup.db'"
```

و جداگانه `data/gallery`، `data/accounts` (نشست‌ها و لاگ‌ها) را کپی کنید. برای PostgreSQL، بک‌آپ دیتابیس جداست و پوشهٔ `data` جای آن را نمی‌گیرد.

بازیابی: ابتدا سرویس را متوقف کنید، سپس `data/` و `.env` را از بک‌آپ برگردانید و یک بار اجرا کنید. مهاجرت SQL افزایشی است و دادهٔ قدیمی را پاک نمی‌کند.

## ۷. قاعدهٔ تک‌فرایندی

فقط **یک** فرایند Uvicorn مجاز است:

```powershell
python -m uvicorn app:app --host 127.0.0.1 --port 8081 --workers 1
```

- دو فرایند یا `--workers 4` باعث می‌شود دو scheduler و دو مجموعه worker روی یک دیتابیس و پورت‌های worker رقابت کنند؛ نتیجه، Job تکراری/گم‌شده و پورت اشغال است.
- `--reload` با Job فعال ممنوع است؛ بارگذاری مجدد، نشست‌ها و workerها را قطع می‌کند.
- فقط روی loopback (`127.0.0.1`) گوش دهید. برای دسترسی عمومی، TLS، reverse proxy، فایروال و احراز هویت قوی لازم است و همچنان یک فرایند اپلیکیشن.
- چند replica و PostgreSQL هم‌زمان، پشتیبانی‌نشده و تأییدنشده است.

## ۸. شکاف‌های نگهداری و retention

این نسخه retention خودکار ندارد. این مسیرها با گذشت زمان رشد می‌کنند:

| مسیر | محتوا | رفتار فعلی |
|---|---|---|
| `data/gallery` | اصل تصاویر | حذف Job، فایل را حذف می‌کند؛ retention خودکار برای خروجی‌های قدیمی نیست |
| `data/previews` | WebP مشتق | پس از حذف Job ممکن است باقی بماند؛ پاک‌سازی خودکار ندارد |
| `data/exports` | ZIP موقت | پس از پایان دانلود پاک می‌شود؛ kill سخت ممکن است فایل موقت باقی بگذارد |
| `data/accounts/<id>/worker.log` | لاگ worker | بدون rotation رشد می‌کند |
| `data/hub.db` و `-wal`/`-shm` | Jobها، history، تنظیمات | بدون prune؛ با WAL فایل‌های جانبی وجود دارند |
| `data/accounts/<id>/gateway` | کپی دروازه و auth | نشست و نسخهٔ کپی؛ حذف دستی فقط با آگاهی |

`scripts/audit_gallery.py` فقط گزارش می‌دهد و هیچ فایل/ردیفی را حذف نمی‌کند. حذف/پاک‌سازی دستی فقط پس از بک‌آپ و با آگاهی از orphanهای احتمالی انجام شود. لاگ‌ها را می‌توانید پس از Stop کردن workerها به‌صورت دستی کوتاه/چرخشی کنید.

## ۹. بهره‌برداری روزانه

- **Accounts:** ساخت، ویرایش، Start/Stop، Pause/Resume صف، آرشیو/بازگردانی. توقف dispatch دادهٔ queued را حذف نمی‌کند و Job فعال را نمی‌کشد.
- **Image Studio:** پرامپت، `n`، نسبت و ترجیح. `Best/Balanced/Draft` راهنمای پرامپت است، نه کیفیت رسمی.
- **Gallery:** صفحه‌بندی پایدار، پیش‌نمایش سبک، دانلود اصل و ZIP هر Job.
- **Operations:** ظرفیت، هدف، Pause سراسری و تاریخچهٔ تغییرات. تغییر تنظیمات Gateway تا Stop/Start worker خالی اعمال نمی‌شود؛ Job در حال اجرا را قطع نکنید.
- **Analytics:** فقط شمارش خروجی‌های ذخیره‌شده و خطاها را ملاک بگیرید، نه تعداد Job یا هدف را. آمار با Gateway و دادهٔ آزمایشی، پیش‌بینی Plus نیست.

## ۱۰. هشدار ایمنی و شرایط استفاده

- این ابزار برای یادگیری و تست محلی است. استخراج خودکار خروجی ChatGPT با مرورگر ممکن است خلاف شرایط استفادهٔ OpenAI باشد و به محدودیت/تعلیق حساب منجر شود.
- از حساب اصلی و حساس استفاده نکنید؛ حساب آزمایشی مجاز و جدا بسازید.
- محدودیت‌های ارائه‌دهنده را دور نزنید: نه چرخش خودکار حساب، نه حل CAPTCHA، نه مخفی‌سازی ضدتشخیص.
- پنل و دروازهٔ worker را عمومی نکنید. نشست‌ها، رمزها و کلیدها را در log، پیام یا مستندات نگذارید.
- `Best/Balanced/Draft` و اعداد ظرفیت، سیاست نرم‌افزارند؛ ظرفیت واقعی Plus اندازه‌گیری و تأیید نشده است.
- PostgreSQL، Cloudflare/Turnstile، ورود واقعی Plus و ۵۰۰ تصویر در ۵ ساعت در این نسخه **تأییدنشده** هستند.

برای ظرفیت و حالت‌های خرابی، [OPERATIONS_V6_FA.md](OPERATIONS_V6_FA.md) را ببینید.
