# Quality Loop — بازبینی و اصلاح هوشمند تصویر

> نام قابلیت: **Quality Loop** (فارسی: حلقهٔ کیفیت). گزینه‌ای per-job در Image Studio و مجموعه‌ای از تنظیمات سراسری.

## این قابلیت چه می‌کند؟

بعد از تولید تصویر، همان تصویر **در همان چت ChatGPT** بازبینی می‌شود:
- اگر متن/اعداد درست باشند: مدل می‌گوید **«آماده است»** و هیچ تولید اضافه‌ای انجام نمی‌شود؛
- اگر حرف/رقم اشتباه باشد: یک پرامپت اصلاحی در **همان conversation** فرستاده می‌شود و تصویر جدید تولید و دوباره نمره‌دهی می‌شود.

## تنظیمات

### در Studio (هر Job)
| گزینه | رفتار |
|---|---|
| Off | بدون بازبینی (یا تابع تنظیم سراسری) |
| 1 round | بازبینی + حداکثر ۱ اصلاح |
| 2 rounds | حداکثر ۲ اصلاح |
| 3 rounds | حداکثر ۳ اصلاح |

### سراسری (Operations)
| کلید | مقدار |
|---|---|
| `quality_gate` | 0 خاموش · 1 فقط بازبینی · 2 بازبینی + ۱ اصلاح |
| `quality_threshold` | 1..10 (پیش‌فرض 8) |
| `QUALITY_GATE` / `QUALITY_THRESHOLD` | seed اولیه از env |

## معیار نمره‌دهی (سخت‌گیرانه)

مدل باید فقط یک JSON بدهد:
```json
{"text_score":0-10,"numbers_score":0-10,"spelling_score":0-10,
 "layout_score":0-10,"overall":0-10,"issues":["..."],"verdict":"pass|fix"}
```
- هر حرف/رقم غلط ⇒ `fix` (حتی اگر بقیهٔ نمره‌ها ۱۰ باشند)؛
- `overall` از ضعیف‌ترین نمرهٔ متنی/عددی بالاتر نمی‌رود؛
- RTL، نیم‌فاصله، اعداد فارسی/لاتین و متنِ داخل کوتیشن («…») چک می‌شود.

## پرامپت مستر و شخصی‌سازی آن

به‌جای ساختن پرامپت در هر بار، **یک پرامپت اصلی (rubric)** وجود دارد و پرامپت کاربر داخل آن قرار می‌گیرد:

```
... شما بازرس کیفیت هستید. درخواست کاربر:
{request}
... چک‌های اجباری متن/عدد/کوتیشن ...
```

- **پیش‌فرض:** `quality_gate.DEFAULT_REVIEW_PROMPT` (در کد، نسخه‌دار)
- **شخصی‌سازی:** از Operations → *Quality Loop rubric prompt (advanced)* یا API:
  ```bash
  GET    /api/quality/prompt      # {template, default, is_custom, hash, placeholder}
  PUT    /api/quality/prompt      # {"template": "...{request}..."}  (apy/CSRF)
  DELETE /api/quality/prompt      # بازگشت به پیش‌فرض
  ```
- اعتبارسنجی: حداقل ۸۰ کاراکتر، حداکثر ۱۲KB، و **الزام وجود `{request}`**.
- جای‌گذاری با `replace` انجام می‌شود (نه `format`)، پس پرامپت کاربر می‌تواند `{}` داشته باشد.
- فایل override: `data/quality_review_prompt.txt` (mode 0600) + audit بدون محتوای حساس.
- در `quality_meta` هر Job: `prompt_source` (default/custom) و `prompt_hash` ثبت می‌شود (فعلاً در سطح ماژول؛ برای قالب سفارشی hash هم در پاسخ API هست).

## محافظ‌ها و هزینه

- حداکثر ۳ چرخه، بدون حلقهٔ بی‌پایان؛ هر چرخه یک تولید اضافه (سهمیه) فقط وقتی ایراد متنی/عددی باشد.
- خطای بازبینی/اصلاح هرگز Job را fail نمی‌کند؛ بهترین تصویر تا آن لحظه تحویل می‌شود.
- نسخهٔ اول و تاریخچهٔ نمره‌ها/ایرادها در `quality_meta` می‌ماند.
- اگر نسخهٔ اصلاح‌شده نمرهٔ بهتری نگیرد، همان نسخهٔ قبلی نگه داشته می‌شود.
- مجوزها: GET ادمین، PUT/DELETE با CSRF.

## جریان کامل

1. تولید تصویر (gateway) → برگشت `conversation_id` واقعی (پچ `ninja:quality-gate`).
2. Execution: بازبینی با پرامپت مستر + پرامپت کاربر → JSON نمره.
3. اگر pass: تبدیل به completed با نمره.
4. اگر fail و rounds باقی: پرامپت اصلاحی در همان چت → تولید مجدد → بازبینی → فقط اگر بهتر بود، «بهترین» عوض می‌شود.
5. ذخیره‌سازی نهایی: تصویر بهترین + meta (history, score, verdict, original_urls, refined_urls).

## محدودیت‌های صادقانه

- نمره‌دهی مدل **قطعی نیست**؛ ممکن است خطا را نبیند یا اصلاح، ترکیب را کمی تغییر دهد. برای متن‌های حیاتی، مسیر تضمینی **تایپوگرافی واقعی (Overlay)** است.
- هزینه: هر اصلاح = یک تولید اضافه؛ برای تصویر بدون متن، Off بگذارید.
- نیاز: بعد از آپدیت workerها Stop→Start شوند تا پچ‌های gateway اعمال شوند.
